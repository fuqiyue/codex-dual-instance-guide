02

AI 按这四步创建第二个入口。

每一步都有明确的结果。首次没有登录缓存，也可以创建和启动。

  1. 1 / 检查安装包

    检测当前用户的 OpenAI.Codex 包、PowerShell 5.1 与真实启动入口。

  2. 2 / 保存通用脚本

    读取完整源码，检查后保存为长期保留的 UTF-8 BOM 脚本文件。

  3. 3 / 准备 Codex 2

    先只读检查，再创建独立账号目录、文件凭据配置和桌面快捷方式。

  4. 4 / 打开并登录

    你在第二窗口自行登录，AI 核对窗口与后端隔离。

保存脚本后，先检查再创建。

示例保存位置为文档文件夹下 CodexLaunchers\Start-Codex-Second.ps1。源码可从下方链接读取。不要逐行粘贴脚本正文，也不要直接执行未经检查的网络响应。

只读检查 · 不启动、不写入
$launcherFile = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'CodexLaunchers\Start-Codex-Second.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $launcherFile -CheckOnly
在同一 PowerShell 窗口创建桌面入口 · 不启动
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $launcherFile -CreateShortcutOnly

检查并创建成功后，双击桌面 Codex 2。新目录没有认证文件时，直接在第二窗口完成登录；不需要从原账号复制文件。

03

两套状态目录，分别存储。

目录由当前用户的本地应用数据位置确定。

内容第二个 Codex 的默认位置
后端配置、认证与会话%LOCALAPPDATA%\OpenAI-Codex\Profiles\Second\codex-home
桌面缓存与界面状态%LOCALAPPDATA%\OpenAI-Codex\Profiles\Second\user-data
桌面入口Codex 2；长期引用已保存的启动脚本

默认实例名是 Second，可通过 -InstanceName 指定另一组目录。脚本不会自动合并历史聊天；两个窗口打开同一个项目目录时，仍共用项目文件。

04

双开成功，要看这些证据。

提交启动请求与验证独立账号，是两个不同步骤。

窗口和后端都分开

  • 两个窗口同时保留，分别显示预期账号。
  • 各自所属后端使用不同的 CODEX_HOME。
  • 第二实例使用独立 user-data。
  • 重复点击 Codex 2 复用自己的窗口。

检查目录即可，不展示认证内容或完整进程环境。无法读取某项时应标为尚未验证。

退出时分别处理

当前应用可能让两实例共用一个原生托盘标识。关闭窗口，或在托盘只退出一次，可能留下另一实例。

完成工作后，在两个窗口分别按 Ctrl+Q，等待正常退出并核对所属后台进程。并发方式异常时，可先退出再使用 -Sequential 顺序切换。

05

给 AI 的完整执行要点。

此摘要可直接读取，不依赖页面交互。完整契约见 AI 创建指南。

  1. 动态发现官方安装包与 manifest 入口；使用 Windows PowerShell 5.1，不写固定安装版本或用户名。
  2. 读取 完整启动脚本，保存到本地长期目录，再检查语法及 -CheckOnly 结果。
  3. 使用新的独立后端与桌面目录，拒绝与主目录重合或目录链接造成的共享；新配置使用文件凭据存储。保留已有配置并核对其隔离条件。
  4. 只有新进程设置 CODEX_HOME 与内部 CODEX_ELECTRON_USER_DATA_PATH，并带对应 --user-data-dir。移除继承的外部 SQLite 路径覆盖和 API/token 变量，当前进程环境随后恢复。
  5. 用 -CreateShortcutOnly 创建隐藏辅助 PowerShell 的桌面入口；用户在第二窗口自行登录。
  6. 核对窗口身份、后端目录、独立桌面缓存与重复点击行为。明确未验证边界，交付脚本位置和退出方法。
需要安装第二份 Codex 吗？

不需要。此方法复用已经安装的官方应用，使用不同后端目录与桌面缓存创建第二实例。

新窗口没有聊天记录，正常吗？

首次使用新目录时正常。登录后产生自己的本地状态；如果第二实例目录已存在，会保留其原有数据，不清空。教程不复制主账号认证或历史记录。

这是官方保证兼容的功能吗？

底层方式在 Windows 安装包 26.1007.2314.0 的双实例场景中已实测。通用脚本通过语法和隔离样本检查，但新账号在线登录须在使用者电脑确认。内部桌面目录变量没有找到官方长期兼容保证；更新后要重新核对。
