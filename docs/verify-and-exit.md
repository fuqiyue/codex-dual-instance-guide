# 验证两个实例并正常退出

[返回首页](../README.md) · [AI 创建指南](../AI-SETUP.md)

## 创建成功看什么

创建快捷方式成功，只能证明入口已生成。第二窗口启动后要核对：窗口显示的账号、所属后端 `CODEX_HOME`、独立桌面 `user-data`，以及重复点击能否复用第二账号的窗口。

保留原始窗口再打开 **Codex 2**。第二窗口未确认身份前，不要在原窗口退出登录或切换账号。检查进程时只记录所需目录，不能输出完整环境或登录令牌。

第二账号首次使用新目录时没有历史聊天是正常现象。用户自行登录后逐渐产生自己的记录；已存在的第二实例目录会保留其原有数据。同一安装包的两套本地历史不自动合并。

## 为什么托盘可能只有一个图标

已审查的 Windows 安装包按发行渠道使用固定的原生托盘 GUID，而不是按账号分配。两个独立窗口仍可能共用一个图标标识；任务栏也可能把窗口归入同一应用分组。

托盘菜单退出只退出所属实例。关闭窗口也可能留下后台。分别进入两个窗口按 `Ctrl+Q`，等待正常保存和清理；核对桌面进程及其后端是否退出。不要用一次托盘退出作为全部退出的证据。

## 第二实例没有独立打开

先检查安装包是否更新、启动脚本是否从文件运行、第二目录是否与主账号重合、是否设置了独立桌面目录变量。不要只修改快捷方式名称来试探。

暂时无法并发时，可在完成工作并正常退出原实例后，用脚本 `-Sequential` 顺序切换。保留第二实例目录中的数据；脚本不会强制退出已有窗口。

## 并行写入的范围

账号目录分开，不代表项目文件分开。两个窗口都编辑同一项目文件时仍可能相互覆盖。按任务划分文件；同一 Git 项目的并行改动可使用独立 worktree，端口和外部数据库还须另行分配。

## 验证边界

内部启动方式在 Windows 安装包 `26.1007.2314.0` 的独立双实例场景中实测过。通用脚本的准备逻辑和语法可用隔离样本核验；每台使用者电脑的第二账号登录与真正双开须实际确认。没有找到官方对内部桌面目录变量的长期兼容性保证。
